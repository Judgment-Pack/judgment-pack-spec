## Findings and verdict (verbatim)

**Verdict: mergeable after fixes F1–F6 below.** I found two MAJOR and four MINOR issues, with no BLOCKER.

Round 1 reviewed `2ac6baab44ffd2d6d5b87916e51cd73a854cbaf0`, using the diff, working tree, repository history, and supplied runtime snapshot. Reviewer: OpenAI Codex, GPT-6; date: 2026-09-21. The commit identifies Claude Fable 5.1 as drafting assistance.

File references below distinguish **spec** from **runtime**.

1. **F1 — MAJOR: retained evidence directly contradicts the scope decision.**

   Exact sentence, spec `rfcs/0002-judgment-graph.md:51–54`:

   > Finding 4 reports a *forward entitlements / cross-decision references* residue family — "insurance enables full refund if…" was left out of the Book-flight pack because it belongs to the Cancel decision, and one pack cannot reference another's outcome — which is exactly the edge this format proposes.

   The same RFC’s Study 004 account says the grammar closed none of the five items and identifies effect/entitlement constructs on four (`:86–95`). The amendment then expressly excludes those constructs (`:155–156`). The earlier “exactly the edge” characterization is therefore no longer the proposal’s position.

   **Smallest fix:** replace the final clause with “which motivated this proposal, but which Study 004 subsequently showed the prototype’s edge did not express; the scope decision below leaves effect/entitlement constructs outside this format.”

2. **F2 — MAJOR: the scope rationale presents an unmeasured use case and a design judgment too categorically.**

   Exact sentences, spec `rfcs/0002-judgment-graph.md:319–322`:

   > The scope is the seam between decisions that different parties own.

   > Between systems the upstream verdict is usually already made: it arrives as a record, not as a pack to run.

   Also, at `:160–162`:

   > An edge that carried that would be a rule about another pack's rules, which is the first step of the general-purpose rules language the non-goals exclude.

   The RFC’s own Evidence section explicitly says the between-systems case **could not occur in Study 004’s frame** (`:96–102`). The implementation establishes project-local composition, not an ownership boundary or the prevalence asserted by “usually”: runtime `internal/graph/graph.schema.json:30,53–68` and `internal/graph/evaluate.go:210–225`.

   Non-goals (`docs/non-goals.md:12`) excludes a general-purpose rules language; it does not establish that any entitlement construct necessarily starts one. That is a maintainer’s design argument, not a measured result.

   **Smallest fix:** describe independently owned decisions as an **intended, unmeasured use case** of the selected dataflow seam; make receipt of an already-recorded verdict conditional rather than “usual.” Apply that qualification also at `:154–155` and `:173–175`. Attribute the non-goal inference explicitly: “The maintainer judges that extending edges this way risks growing toward the general-purpose rules language the non-goals exclude.”

3. **F3 — MINOR: `absent` does not unconditionally engage required-evidence handling, and the guidance requires source support.**

   Exact sentence, spec `rfcs/0002-judgment-graph.md:330–332`:

   > The prototype's default, `unknown`, is the second; its `absent`, which engages the downstream pack's required-evidence rule, is a claim about the *upstream* that only the graph's author can make.

   A feed may target an optional evidence requirement. The resolver skips requirements whose `required` member is false, and applicability can return before required-evidence handling: runtime `resolve.go:79–109` (`runtime:internal/evaluation/resolve.go:79`).

   The authoring guidance permits `absent` **only when the source says** a decision producing no outcome is the missing evidence, rather than assigning the graph author independent authority: runtime `internal/mcp/prompts.go:524–527`.

   **Smallest fix:** qualify required-evidence handling with “when the target requirement is required and the downstream pack is applicable,” and replace “only the graph’s author can make” with “the graph’s author must ground in the source.” The corresponding retained wording at `:299–301` should receive the same requiredness qualification.

4. **F4 — MINOR: `result` is misclassified as an evaluator switch.**

   Exact sentence, spec `rfcs/0002-judgment-graph.md:134`:

   > The document carries two switches whose meaning is evaluator behavior.

   `onUnresolved` changes the evidence state supplied downstream. `result` names a node: its schema description calls it the composite’s headline, and evaluation selects that headline **after** evaluating the nodes. It changes neither their inputs nor their dispositions. See runtime `internal/graph/graph.schema.json:43–45,99–102` and runtime `evaluate.go:400–430` (`runtime:internal/graph/evaluate.go:400`).

   **Smallest fix:** say “The document carries an evidence-handling switch, `onUnresolved`, and a structural result-node reference, `result`.” Correct the repeated “two switches” wording in spec `CHANGELOG.md:118`. The subsequent rejection of “no evaluation semantics” remains supported by `onUnresolved` alone.

5. **F5 — MINOR: the validation summary needs target scoping and a more exact account of cycle reporting.**

   Exact sentence, spec `rfcs/0002-judgment-graph.md:234–238`:

   > The implementation does give the other cases a concrete form worth borrowing: a dangling pack reference, an edge naming an undeclared node, a self-edge, a `result` naming an undeclared node, two edges feeding one fact pointer or one evidence requirement, two fact pointers where one is a prefix of the other once their RFC 6901 tokens are decoded, and a cycle, reported by strongly connected component.

   Duplicate and overlapping feeds are prohibited **within the same target node**; different nodes can use identical pointers or requirement ids. The implementation also rejects pointers exceeding **64 decoded reference tokens**, a material boundary absent from this list. See runtime `document.go:361–389` (`runtime:internal/graph/document.go:361`).

   Strongly connected components determine cycle membership, but the report does not preserve component groupings: it emits one diagnostic containing the sorted union of cyclic nodes (`document.go:398–400,579–642`).

   **Smallest fix:** add “of the same target node” to both collision descriptions; mention the 64-token limit; replace “reported by strongly connected component” with “whose cyclic node membership is determined using strongly connected components.”

   Additional validation findings outside that sentence include carrier/schema/version failures, unreadable or undecodable evidence-target packs (`document.go:175–243,428–447`), and the configured rows-path containment check (`internal/graph/suite.go:197–216`). The list should not imply exhaustive coverage.

6. **F6 — MINOR: the historical accounting overstates both the release count and the table’s completeness.**

   Exact sentence, spec `rfcs/0002-judgment-graph.md:18–19`:

   > It is now governed by eight, released across five runtime versions, and they are named.

   The table’s eight records first shipped across **four** versions: `0.8.0`, `0.10.0`, `0.18.0`, and `0.19.0`. The separate graph-test increment makes `0.9.0` a fifth release in the narrative.

   “Governed by eight” also reads as exhaustive, although the described surface inherits other decisions, including reviewed-set locking, audit records, and trace semantics. Runtime `docs/adr/README.md:114–134` records those relationships; graph evaluation directly implements ADR-0019 and ADR-0033 behavior.

   The ADR-0015 table cell additionally says:

   > the standalone graph document, the `experimental graph` verbs, and a tested position on each of this RFC's open questions

   ADR-0015 addresses the **five original questions**, not the four added by this amendment: runtime `docs/adr/0015-experimental-graph-surface.md:61–93`.

   **Smallest fix:** introduce the table as “eight graph-specific decision records, first released across four versions,” with the separate test increment accounting for the fifth version. Change “each of this RFC’s open questions” to “each of its five original open questions.” Carry the accounting correction into spec `CHANGELOG.md:115`.

- **Identity and references:** the closed node schema allows `pack` plus an optional description, with no pack version, digest, remote reference, registry reference, or cross-project reference. `Project.Entry` resolves the project-local key (`internal/project/project.go:533–569`). - **Validation versus evaluation:** the structural gate reads the graph and configured ids, without reading packs. Evaluation invokes that gate; graph validation adds the evidence-requirement reference checks. The evaluator subsequently handles malformed packs and undeclared evidence inputs in its own error ordering. The amendment’s distinction is correct; see runtime `internal/graph/document.go:291–304,405–450` and `evaluate.go:140–167`.

- **Pins and locks:** `expectedVersion` is optional and checked by `packs validate`; graph evaluation does not consult it (`internal/project/jpack.schema.json:89–92`, `validate.go:192–200`). Graph evaluation supplies the per-node lock check; graph tests leave it unset. `packs verify` separately reads the lock to verify the tree. This is confirmed by runtime `internal/cli/app.go:283–310`, `internal/cli/graph.go:247–280,400–404,445–449`, `internal/mcp/tools.go:1049–1072`, and ADR-0028 `:60–84`.

The three tools are `experimental_test_graphs`, `experimental_list_graphs`, and `experimental_get_graph` (`internal/mcp/tools.go:162,186,195`). There is no graph-evaluate MCP tool among them.

Runtime `CONFORMANCE.md:51–70` expressly includes both graph verbs and covers the conforming inputs reaching the shared evaluator. The envelope remains a runtime convention, and its label points to the claim rather than making a separate claim (`internal/result/graph.go:5–20`). “Claims nothing” is defensible here as **no composition conformance claim**, not a denial of the evaluator’s claim.
