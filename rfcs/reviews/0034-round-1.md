## Clean-room review: disposition

One read-only review of RFCs 0034–0038, as the interim regime for RFC pull requests asks. The maintainer waived the different-vendor review for these RFCs (RFC 0034, Unresolved question 1). **Same vendor, not a cross-vendor claim.**

The review was asked to check two things in particular: whether the kind-declaration and emitter-contract surfaces can carry "never remove in 1.x", and whether RFC 0038's refusal rules are testable as written.

Every finding is fixed in this PR, in cab220e7.

| # | RFC § | Severity | Finding | Disposition |
|---|---|---|---|---|
| 1 | 0036 §1–3, 0034 §8 | HIGH | Exact selectors and closed members, with no way for an emitter or loader to say which versions it accepts, so any 1.x addition breaks them | Fixed. The manifest has `requestVersions`, and the host writes the highest one it supports or refuses (`EMIT-REQUEST-VERSION`). 0034 §8: a writer writes the lowest selector that expresses the document, and consumers declare the selectors they accept. |
| 2 | 0036 §7 | HIGH | "a new check starts as a warning for one minor" tightens rules within 1.x | Fixed. Harness levels (`vectors/harness.json`): a check that can fail is added only at a new level, which authors opt into. |
| 3 | 0037 §6 | HIGH | `input: "factsContracts"` was undefined for `reads`, `environments`, request steps and harness checks, and "a host that predates it" contradicted shipping both in 1.0 | Fixed. Defined in 0036's first manifest and request formats (§1 `input`, §2 the facts-contracts form, §5 checks 4 and 5 for this form). 0037 §6 and Compatibility now point to it. |
| 4 | 0036 §1, 0034 UQ3 | HIGH | SemVer ranges assumed compatibility rules that 0034 left open, and there was no deprecation path for manifests, checks, selectors or codes | Fixed. 0034 §2.4 sets kind version rules (a minor only widens; `kind`, `entryId`, `secrets` and `references` are fixed). 0034 §8 adds a deprecation status for codes, selectors, members, rules and kinds. The manifest gains `deprecated` (`EMIT-DEPRECATED`). |
| 5 | 0036 §5 check 5 | HIGH | "never partially" was not decidable | Fixed. It fails on a run of at least 32 characters of a reference outside a complete occurrence. 32 is longer than any project id (30). |
| 6 | 0038 §2 step 5 | HIGH | The mirror check came before selection and its scope was unclear; outputs and `prior_state` were required but never read | Fixed. Every resource of the read section, selected or not, needs its mirror. The read section is `resource_changes` for a plan and module resources for state. Outputs, `prior_state` and `planned_values` are never read (outputs are UQ4). |
| 7 | 0038 §2 step 6 | HIGH | Removing a sensitive array element shifts later indices | Fixed. The whole array is removed, up to the nearest object member, and `after_unknown` pointers under a removal are dropped. |
| 8 | 0038 §2, §4–5 | MEDIUM | Hash on oversize, depth origin, removal count, address anchoring, `-0` and exponents, empty state | Fixed. The sha256 covers the whole file; the top level is depth 1; one count per removed member; the address match is whole; numbers in normal form, with `TF-NUMBER` over 64 characters; a state without `values` is empty. |
| 9 | 0038 §3 | MEDIUM | A table growing by patch makes two readers disagree | Fixed. The table has its own release number, named by claims, vectors and the acquisition record (`formatTable`). |
| 10 | 0038 §2, Security | MEDIUM | Diagnostics said both "code and sha256" and "pointers", and a pointer before removal can carry a sensitive key | Fixed. A diagnostic carries the code, sha256 and size only, and a vector asserts this. |
| 11 | 0037 §5 | MEDIUM | `FACTS-OPTIONAL-UNHANDLED` can never fire: Core §6.5 requires `onUnknown` | Fixed. The code and its UQ are removed. Premise verified in Core. |
| 12 | 0037 §1 | MEDIUM | The example pointer disagreed with §2's key | Fixed (`/references/~1database/...`). |
| 13 | 0037 Conformance, 0034 §1 | MEDIUM | "negative zero refused" had no rule, and "round-trips" did not say text or value | Fixed. 0034 §1 defines round-trip by value (`1.50` admitted, `0.10000000000000001` not) and refuses negative zero (`REG-DOC-NUMBER`). |
| 14 | 0035 §3 | MEDIUM | `REF-SECRET-PIN` and `REF-SECRET-FORM` overlapped | Fixed. An ordered precedence: PIN only for a floating version or a project number, and FORM for zero, a leading zero or ten digits. |
| 15 | 0034 §2, 0035 §2 | MEDIUM | A custom `entryId` could allow ids no reference can name | Fixed. Ids are also held to RFC 0035's `entry-id` grammar. |
| 16 | 0036 §3–4 | MEDIUM | Standard error passthrough and `env` values could reach CI logs | Fixed. Standard error is discarded unless `--emitter-stderr` is given, `env` values are never printed, and Security says so. |
| 17 | 0036 §1 | LOW | Manifest members incomplete; `command` path rule unclear | Fixed. Closed member list; `command[0]` is a bare program name on `PATH` or a path inside the repository. |
| 18 | 0035 Evidence | LOW | Wording narrowed the adopter | Fixed. The wording is now general. |
