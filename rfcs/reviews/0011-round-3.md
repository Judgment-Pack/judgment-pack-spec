## Findings (verbatim, unedited)

1. RA-1 — MAJOR — Section: RFC 0011, Unresolved #8 (“Bootstrap”). Declaring “the minimal trust assumption” to be two out-of-band pins retroactively changes the merged consumer step: Specification §2 requires a series-bound authority key and persisted minimum accepted head, while Security calls that key the registry’s trust dependency and Unresolved #1 leaves publisher and neutral-log artifacts distinct. A publisher key can authenticate an initial signed history without a separate genesis pin; a neutral-log model may require more than two trust artifacts; and a genesis pin cannot prevent the signer forking after the common genesis. “Below the genesis pin … trust-on-first-use” is likewise inaccurate: the authority authenticates the first view, while global uniqueness and recency remain unestablished. Fix: recast the item as questions about whether an independently supplied checkpoint is necessary under each signer model, what threat it addresses, and whether any checkpoint or trust bundle suffices; remove “minimal,” “two-pin minimum,” and the TOFU assertion unless Specification, Security, and Conformance are substantively amended. (`rfcs/0011-judgment-currency-anchor.md`, Specification §2, Security and privacy, Unresolved #1/#8/#9; `rfcs/reviews/0011-round-1.md`, R-7 and R-9 dispositions.)

2. RA-2 — MAJOR — Section: RFC 0011, Unresolved #9 (“convergence with RFC 0010”). “Need the same underlying primitive” inflates a related external-witness concern into an identity and misrepresents RFC 0010: its Specification §2 names the gateway-specific prerequisite that count-only seals must first become content-binding, while external checkpointing is §4, where checkpoints are gateway-signed and witness forms are expressly non-interchangeable—not necessarily a hash-chained, independently signed checkpoint log. RFC 0010 Unresolved #1 even leaves whether anchoring is worth adopting open; RFC 0011’s registry already has content-bound hash chaining. The asserted shared artifact is therefore a design requirement disguised as convergence and has no named external owner, contrary to RFC 0000’s placement rule and RFC 0011’s load-bearing scope. Fix: cite RFC 0010 §§2 and 4 separately, describe only potentially shared witness properties, and ask whether any mechanism can satisfy both threat models; otherwise amend the scope and destinations through a separately reviewed proposal. Study 016 does not establish this cross-record identity: its frozen/not-run caveat is accurate and keeps it at measurement-plan strength. The live GitHub page was unreachable during review; that status was verified against the local checkout’s last-fetched `origin/main` commit `2877e29` (`studies/016-policy-currency-anchor/README.md`, Status; `PREREGISTRATION.md`, “The freeze and the primary attempt” and §4c), whose tree has no `results/`. (`rfcs/0010-gateway-signing-identity.md`, Specification §§2 and 4, Alternatives, Unresolved #1; `rfcs/0011-judgment-currency-anchor.md`, scope note, Specification §§1 and 3, Unresolved #9; `rfcs/0000-rfc-process.md`, “Cross-project exploratory records”; `rfcs/reviews/0011-round-1.md`, R-4 and R-11 dispositions.)

3. RA-3 — MAJOR — Section: RFC 0011, Unresolved #9 (“single-operator ceiling”). The claim that Security already states “this bound for the neutral-log model” changes the actor and regresses R-9: Security says a neutral log cannot alone expose publisher equivocation to an isolated verifier, whereas #9 describes one operator controlling both the currency-signing key and history. That collapses publisher assertions, currency authority, and log-inclusion signatures into one signer model. “Would buy back” and “can still be caught equivocating” also overclaim: witnessing makes equivocation observable only under still-unspecified retention, cross-view comparison, verifier-enforcement, independence, and non-collusion assumptions; persisted state already catches some sequential conflicting views. Fix: distinguish publisher equivocation, registry/log split views, and RFC 0010’s post-key-disclosure rewrite threat, then replace the categorical detection language with conditional language tied to an explicit witness contract. (`rfcs/0011-judgment-currency-anchor.md`, Specification §2, Security and privacy, Alternatives, Unresolved #1/#9; `rfcs/reviews/0011-round-1.md`, R-9 finding, disposition, and round-two confirmation; `rfcs/0010-gateway-signing-identity.md`, Specification §4 and Security and privacy.)

mergeable after listed fixes
