### 1. MEDIUM: an escaped `;` after a dot segment is still admitted, though the rule's own reason covers it. So are an escaped `?`, `#` and NUL.

**Where.** `spec/dialect.md:751-757` and `rfcs/0018-dialect.md:1564-1570` (byte-equal), plus `rfcs/0018-dialect.md:669-675` and `:694-698`. The §13 entry is at `spec/dialect.md:1765-1772` and `rfcs/0018-dialect.md:2578-2585`.

**Why the rule's reason covers it.** The form refuses `%2e%2e;x`. That refusal only protects against one kind of server: one that decodes an escape and then drops a path parameter. That same kind of server reads `..%3b/admin` or `%2e%2e%3b/admin` as `..;/admin`, then as `..`. An example is a front server that decodes before forwarding, in front of a servlet container that strips path parameters.

**What the readers do.** Both readers admit all of these under the prefix `/guides`, as scope entries and as endpoints, which is what the text says:
- `/guides/..%3b/admin`
- `/guides/..%3B/admin`
- `/guides/%2e%2e%3b/admin`
- `/guides/.%3bx/admin`

**Neighbours of the same kind,** where one decoding step produces a delimiter or a dropped byte. All are admitted too:
- `..%3f`: an encoded `?` read as the end of the path, as in Apache httpd's CVE-2024-38474 ([Black Hat USA 2024 slides](https://i.blackhat.com/BH-US-24/Presentations/US24-Orange-Confusion-Attacks-Exploiting-Hidden-Semantic-Thursday.pdf)).
- `..%23`
- `..%00`: Jetty's CVE-2021-34429 served `/.%00/WEB-INF/web.xml` by reading `.%00` as `.` ([GHSA-vjv5-gp2w-65vm](https://api.osv.dev/v1/vulns/CVE-2021-34429)).

**Why §13 does not cover it.** §13's residual names only double encoding, case folding and "a server's own rewriting". A reader will conclude that one-step spellings are covered, and they are not. The PR body flags `%3b`, but the text does not mention it.

**Recommendation: refuse them in the same clause, still without decoding:** "no segment's part before its first `;`, `%3b`, `%3B`, `%3f`, `%3F`, `%23` or `%00` is a dot segment."
- It costs nothing: no genuine page has a segment that is a dot segment followed by an escaped `;`, `?`, `#` or NUL.
- The rule stays a finite test on spellings.
- Each reader changes one split, e.g. `re.split(r";|%3[bBfF]|%23|%00", segment, 1)[0]` in Python and the same split in TypeScript, with controls for each spelling.

**The minimum** is `%3b`/`%3B`, which the stated reason for refusing `..;` covers directly. If the others stay admitted, §13 should name them: "an escaped `;`, `?`, `#` or NUL after a dot segment, which a server that decodes it reads as a parameter or as the end of the path."

**Confirmed by** running both readers (`.review-scratch/probe.log`) and by reading.

### 3. LOW: "case folding of paths" is not a way out of the prefix

**Where.** `spec/dialect.md:1769-1770`, `rfcs/0018-dialect.md:2582-2583` and `:696-697`, `CHANGELOG.md:264`.

**What happens.** A server that folds path case serves the same resource for another spelling of an in-scope path. The byte comparison then refuses an honest spelling. That is a false refusal, but it does not let a URL inside the prefix reach a page outside it. The case of hex digits is already handled.

**Fix, one of:**
- Name spellings that do escape: an overlong UTF-8 dot (`%c0%ae`), or a full-width dot or solidus that a server normalizes (`%ef%bc%8e`, `%ef%bc%8f`). The probes admit both, as the text says.
- Keep case folding, and say it causes a false refusal, not an escape.

**Confirmed by** reading.

### 4. LOW: the stated cost leaves out the backslash and the discovered URL

**Where.** `rfcs/0018-dialect.md:683-684`.

**What the text says, and what holds.** "A page whose URL carries an escaped slash cannot be read under a scope; an exact-endpoint profile can still read it." The probes bear this out:

**What it does not say:**
- `%5c`/`%5C` pages are refused too. Round 15's record shows the Gateway writes `%5C` itself for a raw backslash in a `Location`.

**Fix.** "A page whose path carries an escaped slash or backslash cannot be read under any scope, the wildcard included; a research run that discovers one fails at admission. Only an exact-endpoint profile naming that URL reads it."

**Confirmed by** running (the probes) and reading.
