# RFC 0018, round 17: dialect format 4.0.0 (#316)

Reviewed `git diff origin/main...HEAD` (one commit, 24 files): `spec/dialect.md` §2.2 and its pointers,
the RFC 0018 amendment, `conformance/dialect/format-4/`, `tools/dialect_verify.py`,
`tools/dialect_builtins_reference.py`, the TypeScript reader's refusal, and the tests. Same-vendor
review, not a cross-vendor claim. No HIGH found. The MEDIUMs are coverage and wording gaps. Not one of
them is a disagreement between text, reader and rows on an input the rows or tests exercise.

## HIGH

None.

## MEDIUM

**M1. The source side of format 4.0.0 has no row and no test.** Every row and every test builds a
dialect with no source (`conformance/dialect/format-4/README.md`, "The rows"). The section claims
"one row for each form and refusal", but these forms and refusals have none:
- a source's `read.rule` of version `2.0.0` (§2.2 table; `tools/dialect_verify.py:1648`);
- `derivation` on a source's lineage, and `{"by": "pointer", "from": Q}` anywhere: no row, vector
  or test writes a `from` in a version 2.0.0 rule and then reads `derivation`;
- a source parameter of a new type (`:1600`), its refusal in format 3.0.0, and the list bounds on a
  source parameter (`:3591`);
- `aheadWithin`'s `asOf`/`maxAhead` in `unsignedParameters` (`:4159`, §2.2.6);
- `admits` over a case-rule target: admission (`:3651`) and "admits names a target no source
  writes" (`:1681`);
- `equalsParam` over a list parameter (`:1209`, "takes any of the six").

Mutation check: each of these changes leaves `tests/test_dialect_format_4.py` passing. The changes:
drop the source `list_bounds`; admit `TYPES_4` for source parameters in every format; pass
`format4=True` to every source read; drop the case rule from admission; stop naming `aheadWithin`'s
parameters; write `{"by": "pointer"}` without `from`; drop a source's `derivations`; restrict
`equalsParam` to scalars; leave the case rule out of `written_facts`. The two format-3 refusal mutants
also pass `tests/test_dialect.py`. Probed by hand, the reader behaves as the text says on each point:
an `admits` of `["record"]` on a case-rule target gives `admission-refused`, and a source rule of
version 2.0.0 gives a `{"by": "literal"}` evidence entry and `{"by": "none"}` for unwritten facts.
Smallest fix: one end-to-end vector with a source whose read is a version 2.0.0 rule writing a
`from`, a literal and a derived value under an `admits` entry, plus rows or reader tests for the
listed refusals.

**M2. `derivation` when no clause matched is not stated.** §2.2.6 (`spec/dialect.md:562`) defines
`derivation` as "how the match wrote it". There is no match for a skipped source
(`tools/dialect_verify.py:3602`) or for a calculator that did not compute (`:3629`). The reader
writes `{"by": "none"}` (`:3905`) for every target there, including the evidence targets a
calculator that did not compute marks `unknown` with `present: true`. A second implementer could
omit the member, or call that evidence `literal`, and get a different preparation digest. Input: a
format 4.0.0 calculated source with a version 2.0.0 rule whose answer status is not `computed`.
Smallest fix: one sentence ("a target of a read that was not applied carries `{"by": "none"}`")
and one row.

**M3. Under `extended`, the `decimal` type's length is two things.** §2.2.2 (`:386`) fixes `decimal`
at "at most 128 characters, Core §4.1's ... ceiling under `base`". §2.2.7 (`:583`) says only the
derived-value and list-element maxima are "the same under every profile", which suggests the other
maxima follow Core §4.1's `extended` column (decimal 256, literal 16384, element 2048). Type
membership decides answers, not only refusals: whether a 200-character decimal string is
comparable, or is a coordinate. Both bundled readers support only `base`, so neither reader shows
this today (unconfirmed impact). Smallest fix: say that the type's length is the profile's
decimal-string ceiling, or that it is 128 under every profile.

## LOW

**L1. Accuracy figure near antipodes.** The reference sweep gives a largest difference of
1.756e-7 mm over 5014 pairs, matching `:541`. A probe of 400 near-antipodal pairs (offsets of 1e-12
to 1e-9 degrees) reached 7.7e-6 mm, about 40 times the stated figure. Example:
(73.945916067075, -120.961330246977) to (-73.945916067075, 59.038669753022). It is still far below
the one-micrometre test bound, and every floor matched the reference. The text already calls the
figure a measurement, so this is not a contradiction. Suggest adding a near-antipodal set to
`sweep` and quoting its figure.

**L2. A pointer written twice in one claim form.** With facts
`[{"pointer": "/x", "from": "/y"}, {"pointer": "/x", "value": 1}]`, the reader writes `1`, gives
`derivation` `literal` (last entry wins, `:3338`), keeps `candidateFrom ["/y"]`, and still fails
`read-failed` if `/y` is absent. `:475` ("in order") implies this for the value but not for
`derivation`. Suggest refusing a repeated pointer within one claim form, or saying that the last
entry wins.

**L3. Wording on readers written before the amendment.** §2.2.7 (`:591`) says such a reader
refuses the document `input-malformed`. That holds only if phases 0 to 3 pass: a format 4.0.0
document with 17 sources is `input-over-bound`. Suggest "in phase 5, as an unknown selector".

**L4. Reference precision.** `:539` says "90 significant digits", but
`tools/dialect_builtins_reference.py:92` runs at `PRECISION + 10` = 100. Suggest aligning the two.

**L5. Open question 12 (`rfcs/0018-dialect.md:1075`).** "An unwrapped `1.5` is compared only as
the string" reads as if the number `1.5` were compared. It is not comparable; only the string
`"1.5"` is. Suggest rewording.

## Checked and found sound

- Every MUST of §2.2.1–§2.2.7 matches the reader (`check_rule_2`, `check_condition_2`,
  `check_derived`, `derive`, `evaluate_2`, `rule_claim_2`, `build`, `unsigned_parameters`). All 158
  rows and the end-to-end vector pass. A fuzz of about 1190 single-member mutations of the case rule
  and case document produced no Python exception: every one ended in a refusal, a finding or a
  reading.
- Determinism of `distance`: only integer arithmetic (`Fraction`, `//`, `math.isqrt`), with no
  floating point and no platform maths library. Each step of §2.2.5 matches the code one to one, and
  nested floor division is the same as one floor division for non-negative integers, so the order
  of operations is fixed. The poles, the antimeridian (±180 is one meridian), identical points,
  `-0`/`-0.0` and coordinates exactly antipodal or 180 degrees apart all give the stated values.
  Out-of-range or non-decimal coordinates give none, never a non-finite value.
- `duration` is exact: §1 timestamps are `Z`-only whole seconds with no leap second. `speed` is
  `⌊d/|t|⌋` and none at `t = 0`. `aheadWithin`/`freshWithin` are inclusive at both ends, and a
  negative window is false.
- Comparison is exact through `Decimal` (`-0` = `"0"`, scale ignored, magnitudes up to 2^53−1,
  129-character strings not comparable). Membership is by code point. The address grammar refuses
  leading zeros, a second `::`, zones, brackets, embedded IPv4 except as the last 32 bits, and host
  bits. Mapped addresses never meet IPv4 ranges.
- Order of checks: list count and element bytes come before the type check. The phase 3 counts
  (derived values, literals, the case rule's clauses, listed conditions and targets) come before any
  form. A reader that does not read the format counts as for 3.0.0, then gives `version-unread` in
  phase 4, in Python (patched) and in TypeScript alike.
- Compatibility: format 2/3/2.0.0/3.0.0 paths are unchanged in code; `tests/test_dialect.py` passes
  (109 tests). The preserved `v0.3.0` `verify.ts` is byte-identical to `v0.3.0`'s file (blob
  `219a598…`, SHA-256 `5ae002b…`, also pinned by both retained-column inventories), and the
  historical and retained release tests pass.
- Version fields: `formatVersion` `4.0.0`, `ruleVersion` `2.0.0` and the preparation's
  `formatVersion` are three-part. No integer `4` is defined. Core stays `0.5.0`, and no schema
  changed.
- The amendment record is honest: proposed, in no claim, second reader and schemas open, round 17 not yet run.
