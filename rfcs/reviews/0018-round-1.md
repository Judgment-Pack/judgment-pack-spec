### Complete output (verbatim, `.review-scratch/findings.md` as the reviewer saved it)

1. **MEDIUM — `spec/dialect.md:712` (also `rfcs/0018-dialect.md:832`): absent bindings have contradictory outcomes.** Findings 7 and 8 apply whenever a record exists, without requiring its `binding` member to exist. An absent binding is not an object of the required kind, so a literal implementation stops at `binding-foreign-kind`, before finding 9 can report `unbound`. The reader instead skips both checks when the member is absent (`tools/dialect_verify.py:1837`). This affects existing vectors: `unbound-record` reports `unbound`, while `unsigned-parameters` succeeds with `absent`. Fix both text copies by explicitly conditioning findings 7 and 8 on a present binding, distinguishing absence from `null`. **Confirmed by reading and running** `.review-scratch/probe.py`.

2. **MEDIUM — `spec/dialect.md:711`; `tools/dialect_verify.py:1827`: citation comparison silently requires equal array lengths.** The text requires comparison “as a set”; the reader also requires equal lengths. Duplicating the valid vector's sole citation, while preserving the binding bytes and every input, produces `record-inputs-differ` although the citation set is unchanged. An independent reader following the text would accept that comparison. Either remove the length condition or explicitly specify uniqueness/multiplicity and its finding in both text copies. **Confirmed by reading and running** the duplicate-citation probe.

3. **MEDIUM — `spec/dialect.md:686`; `tools/dialect_verify.py:1441` and `:1787`: refusal precedence is not implemented as specified.** The text puts all bounds before malformed inputs, then unsupported kinds, before recomputation/findings. A 33-level acquisition result with its original receipt reports `acquisition-invalid` before its depth is checked; malformed dialect JSON plus an over-depth case reports `input-malformed`; a `selected-file` missing required `read` and carrying an invalid provider reports `kind-unread`. Fix the reader to honor the declared precedence, including common source-form validation before `kind-unread`; clarify any intended phase-dependent exceptions in the text instead of leaving them implicit. **Confirmed by reading and running** all three probes.

4. **MEDIUM — `tools/dialect_verify.py:702` (also `:709` and `:712`): malformed rule members escape as exceptions.** An array-valued `op` or `equalsParam.param`, or object-valued `freshWithin.asOf`, raises uncaught `TypeError` during dictionary lookup. Section 11 requires `input-malformed`, not a traceback or missing answer. These are small, valid JSON documents within all resource limits. Validate member types before dictionary/set operations and add malformed-form checks covering these branches. **Confirmed by running** on Python 3.8 and 3.12.

5. **MEDIUM — `tools/dialect_verify.py:311`; `spec/dialect.md:78`: an allowed pointer encounters an unstated interpreter limit.** A copy from `/` followed by 5,000 digits into an empty array raises `ValueError` at `int(token)` under the available Python interpreters. This is a valid JSON Pointer within the document bounds; the number-literal limit does not apply to a string token. The pointer should yield absent and the copy should write nothing. Compare the token's decimal length/value against the array length before converting it, so the implementation does not impose Python's 4,300-digit conversion limit on the format. **Confirmed by running** on Python 3.8 and 3.12.

6. **MEDIUM — `spec/dialect.md:276` (also `rfcs/0018-dialect.md:396`): SQL reuses `parameters` with incompatible forms.** Section 4 requires a source's `parameters` to be an object of dependency declarations; section 4.3 gives the same member an array of SQL bindings. Version 3 adds kinds to version 2, and no override or separate nesting is specified. A SQL source cannot express both upstream dependencies and SQL bindings under these rules. Rename or nest the SQL bindings and state the resulting source form, synchronizing the RFC. Its unclaimable status is honestly stated, but does not resolve this contradiction in the proposed definition. **Confirmed by reading.**

7. **LOW — `spec/dialect.md:653` (also `rfcs/0018-dialect.md:773`): the output reference asks for an undeclarable release.** The decision-policy definition refers to the gateway release “the dialect names,” but the closed output object permits only `outputVersion`, `platform`, and `policies`; none names a gateway release. Explicitly pin this reference to the Status section's `v0.15.0`, or define a release selector and its semantics. Output conformance is correctly deferred. **Confirmed by reading.**

8. **LOW — `rfcs/0018-dialect.md:82`: the summary overstates agreement on all nine vectors.** The companion manifest intentionally accepts `disposition-differs-from-audit`, while the Runner manifest reports `audit-disposition-mismatch`. Evidence and Conformance explain this difference accurately, but “agrees with the Runner on all nine” does not. Say that all nine preparations recompute byte for byte and that reports agree on the shared preparation-verification surface, with the export-only disposition check excluded. **Confirmed by reading and the passing vector tests.**
