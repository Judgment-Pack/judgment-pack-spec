The full reread produced these findings:

1. **R2-F1 — MAJOR: exclusive possession of the salt is not established.**

   **Exact RFC sentence, L145–151:**

   > An acquisition receipt records, under the gateway's signature, what the adapter reported about how it got the bytes: the adapter by name, version and digest; the operator-declared shape; the endpoint; a **commitment** to the statement (query, resource path or tool call) whose salt the caller alone holds; the source's own word about currency (a bookmark, a transaction id, an ETag) or `null`; the transport's peer identity or `null`; the discovered schema by digest or `null`; an integrity token the upstream itself produced, carried verbatim, or `null`; for a page, the digest of each item; and when the adapter received the bytes.

   **Source:** Although SPEC §1.2a uses caller-only shorthand, the gateway’s explicit security qualification says salt possession depends on transport and custody. Anyone able to read the plaintext exchange can obtain it; the reference does **not** provide exclusivity to the caller. [Gateway SECURITY.md, L86–94](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/SECURITY.md#L86).

   **Smallest edit:** Replace “whose salt the caller alone holds” with “whose salt the gateway returns to the caller and does not retain; exclusive possession depends on transport and custody.”

2. **R2-F2 — MAJOR: record-side citation checking is not exhaustive over JSON objects.**

   **Exact RFC sentence, L315–316:**

   > A record's `cites` that is not exactly the grammar is `record-citation-malformed`, never partially read.

   **Source:** The reference scanner bounds the **entire record’s** nesting at 10,000 levels. When a surrounding value exceeds that limit, `recordCitations` returns `cited=false`; the record produces no citation finding, even if it contains a malformed or unresolved top-level `cites`. The existing regression test explicitly requires an over-depth record to remain unread. Its bytes can nevertheless match an action’s `recordDigest`, because candidate hashing happens separately. [Scanner](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/go/verify_v3.go#L472), [bound](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/go/canon.go#L168), [regression test](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/go/verify_v3_test.go#L459).

   Thus §5’s unqualified description of every JSON object carrying `cites` overstates the implementation, even though it follows SPEC §4’s wording.

   **Smallest edit:** Qualify the guarantee as applying to records the reference scanner recognizes, and add:

   > The reference ignores records exceeding its 10,000-level nesting limit in the citation pass; their bytes remain digest candidates, so an action’s digest match does not establish that those records’ citations were checked.

   Apply the qualification in §5 and *Security and privacy*.

3. **R2-F3 — MINOR: structural validity is not the runtime’s only citation-input condition.**

   **Exact RFC sentence, L181–183:**

   > The runtime writes `cites` on every record a run leaves when the caller supplied citations, holds the supplied document to the structural grammar above and to nothing else, and records it as given.

   **Source:** `ParseCites` rejects documents exceeding `MaxCitesBytes = 1 << 20` before parsing. Its boundary test supplies a valid citation padded with legal JSON whitespace: exactly 1 MiB succeeds; one additional byte fails. The CLI also bounds the file read. This applies before rehearsal behavior can suppress recording. [Parser](https://github.com/Judgment-Pack/judgment-pack-runtime/blob/0c8a4b6/internal/audit/audit.go#L180), [boundary test](https://github.com/Judgment-Pack/judgment-pack-runtime/blob/0c8a4b6/internal/audit/audit_test.go#L587), [CLI reader](https://github.com/Judgment-Pack/judgment-pack-runtime/blob/0c8a4b6/internal/cli/app.go#L425).

   **Smallest edit:** Replace “and to nothing else” with “and its 1 MiB document limit, without resolving or verifying citations.” Qualify the rehearsal-acceptance statements in *Evidence*, §3 and *Conformance* with that limit.

4. **R2-F4 — MINOR: the acquisition-member summary loses the command timestamp exception and the origin of page digests.**

   **Exact RFC sentence, L145–151:**

   > An acquisition receipt records, under the gateway's signature, what the adapter reported about how it got the bytes: the adapter by name, version and digest; the operator-declared shape; the endpoint; a **commitment** to the statement (query, resource path or tool call) whose salt the caller alone holds; the source's own word about currency (a bookmark, a transaction id, an ETag) or `null`; the transport's peer identity or `null`; the discovered schema by digest or `null`; an integrity token the upstream itself produced, carried verbatim, or `null`; for a page, the digest of each item; and when the adapter received the bytes.

   **Source:** For `shape: "command"`, there is no adapter-reported observation time: `observedAt` is the gateway’s timestamp when it finished reading the command’s output. For adapter pages, the gateway computes `pageItems` from each item’s canonical bytes, in order; the adapter does not supply those digests. [Gateway SPEC §1.2a](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/SPEC.md#L189), [command and adapter construction](https://github.com/Judgment-Pack/judgment-pack-gateway/blob/03582d9/go/serve.go#L573).

   **Smallest edit:** Replace the final two clauses with:

   > for a page, the gateway-computed digest of each item’s canonical bytes in order; and the adapter-reported observation time, except for `command`, where the gateway timestamps completion of its output read.
