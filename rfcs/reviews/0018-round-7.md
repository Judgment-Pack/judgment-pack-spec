1. **HIGH — Version-3 citation ordering contradicts the released Runner.** `spec/dialect.md:771`, together with the new Runner-compatibility statement at `spec/dialect.md:338`; implemented at `tools/dialect_verify.py:1924` and `tools/dialect-verify-ts/src/prepare.ts:495` (also duplicated in RFC 0018). The Runner unconditionally sorts citations by `callIndex` (`../review-sp-167-runner/internal/runner/mapping_v2.go:470`), including version 3. The specification and both readers instead retain source order. With the same signed, valid two-source inputs whose source-order indices are `[1, 0]`, the Runner produces `[0, 1]`; both readers return `preparation-differs` for that preparation and accept their own reordered preparation. `cites` is the only differing member. Neither new vector exposes this because each has one acquired source. Fix §9.1 and its RFC counterpart to agree with the released ordering for supported kinds, update both readers and the tests currently asserting the incompatible ordering, and keep any proposed research ordering explicit. **Confirmed by running** both readers and the actual Runner through a read-only Go overlay. Evidence: `.review-scratch/citations.py`, `citation-inputs.json`, `citation-{runner,reader}-preparation.json`, `citation-verify.log`, `runner_review_test.go`, `runner-overlay.json`, `runner-probes.log`, and `ts-probes.log`. The local `v0.12.0` tag differs from the reference commit only by release notes.

2. **MEDIUM — The “written empty” list is not the Runner's rule.** `spec/dialect.md:190` and `rfcs/0018-dialect.md:543`, with the equivalence claim at `rfcs/0018-dialect.md:261`. The Runner accepts `admits: {}` and copy `facts: []` / `evidence: []`; both readers reject them. `Admission` is a pointer, so an empty object survives encoding, and `CopyMapping`'s arrays do not have `omitempty`. Indeed, the Runner requires both copy arrays, while the readers accept `copy: {}`. Furthermore, `headers: []`, `query: {}` and `body: {}` all survive the Runner's `asWritten` check: these fields are `json.RawMessage`. The Runner subsequently refuses their `http` kind by name. Excluding `query` and `body` from the empty-member ban is consistent with this preservation, but singling out `headers` is not. Fix the list and corresponding reader checks against actual encoding and validation, including the copy-array requirement; identify any intentional additional restriction as a specification choice instead of the Runner's rule. The top-level `provider`/`facts`/`evidence` ban does match the Runner. **Confirmed by running** `asWritten` and `validateDialect` on the Runner and the same cases through both readers. Evidence: `.review-scratch/runner-probes.log`, `runner_review_test.go`, `python-probes.log`, `ts-probes.log` (`empty-admits`, `copy-*`, `http-empty-*`).

3. **MEDIUM — Python accepts an explicitly supplied null binding; TypeScript refuses it.** `tools/dialect_verify.py:1302`, reached through `tools/dialect_verify.py:2249`. JSON `null` becomes the same `None` used for an absent binding, so a valid bound dialect supplied with `binding=b"null"` yields a reading. TypeScript returns `input-malformed`. §§4.4 and 11 require an object of exactly `dialect` and `sources`, and prohibit a binding beside a dialect with no unbound source. Preserve presence separately from the parsed value, or use an absence sentinel, and validate every supplied binding. **Confirmed by running** both readers on identical inputs. Evidence: `.review-scratch/probes.json`, `python-probes.json`, `ts-probes.json`, case `bound-with-null-binding`.

Neither count implementation checks `R.responses`. Add the research-source response count to phase 3 and test 64/65, including malformed entries so later validation cannot mask the bound. **Confirmed by running** both readers. Evidence: `.review-scratch/extra-probes.py`, `probes.json`, `python-probes.log`, `ts-probes.log`, cases `research-record-well-shaped-64` and `research-record-well-shaped-65`.

5. **MEDIUM — Research acquisition forms are checked as ordinary acquisitions, not as §§4.3/5.2 specify.** `tools/dialect_verify.py:2262` and `tools/dialect-verify-ts/src/forms.ts:805`. With an outer receipt/salts supplied, they instead allow a non-object research record, a missing/non-array `responses`, unknown record members, or malformed retained entries through to `kind-unread`. §11 requires these forms checked before that refusal.
